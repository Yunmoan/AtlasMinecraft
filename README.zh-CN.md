# Atlas

[English](README.md) | [简体中文](README.zh-CN.md)

使用 **Go** 从零编写的 Minecraft **Java 版 1.21.1（协议版本 767）**服务端。运行时不需要 JVM，没有外部依赖，完全基于 Go 标准库。

## 快速开始

```powershell
# 构建，并嵌入 UTC 构建时间（PowerShell，Go 1.23+）
./build.ps1

# 启动；本地配置、存档和日志位于 run/ 下
./start.ps1

# 创建普通主世界，使用纯 Go 实现的地形、洞穴和已支持的装饰生成
./start.ps1 -ServerArgs @("-world", "new-world", "-seed", "1234")

# 加载现有 Java 版 1.21.1 存档的副本
./start.ps1 -ServerArgs @("-world", "world-copy")

# 创建不生成结构和地物的 Java 格式超平坦世界
./start.ps1 -ServerArgs @("-world", "flat-world", "-level-type", "minecraft:flat", "-seed", "1234")

# 启用独立调试日志；玩家登录后可在控制台用 op 授予管理员权限
./start.ps1 -ServerArgs @("-world", "flat-world", "-debug")

# 端到端冒烟测试：通过客户端完整协议流程访问服务端
./test.ps1 -Suite smoke
```

本地配置默认监听 `127.0.0.1:25567`，并启用在线身份验证。请使用 **1.21.1** 客户端。可编辑 `run/server.properties` 修改本地设置，初始模板为 `configs/server.example.properties`。输入 `stop` 保存并关闭服务器。传给 `start.ps1` 的相对世界路径以 `run/` 为基准。

`build.ps1` 输出 `bin/atlas.exe`。也可以直接执行 `go build -o bin/atlas.exe ./cmd/atlas`，但不会嵌入构建时间。直接运行二进制程序时，以当前工作目录为基准；要使用本地存档，应从 `run/` 启动。

## 已支持的功能

- 服务器列表查询：状态 JSON 和 ping/pong。
- 离线模式登录，以及可选的在线模式登录。在线模式支持 RSA、AES/CFB8、Mojang `hasJoined` 验证、官方 UUID 和玩家档案属性；数据包达到 256 字节时启用压缩。
- 完整的 1.20.2+ 配置阶段：品牌信息、**完整的 1.21.1 注册表数据**和功能标记。注册表包括维度类型、64 个生物群系、47 个伤害类型，以及盔甲纹饰、狼、画和旗帜等数据；预先编码为网络 NBT，再通过 `go:embed` 嵌入。
- 游玩阶段：创造模式、加入世界流程、带传送确认的位置同步。
- 通过区块批次传输现有 Java 地形、新生成的普通区块及不含结构的超平坦区块，支持按视距加载和卸载。
- 接受玩家连接前，可配置出生区域预加载，默认准备 7×7 个区块；支持并行生成、确定性的基础地形复用和进度日志。
- 区块任务按玩家当前距离排序，并取消过期的视图请求。传送会取消旧视图中的待处理工作，再并行准备目的地附近区块；地下矿石写入保留高度缓存。
- 多人游戏：玩家列表，按区块距离生成／移除其他玩家实体，相对位置与旋转更新，传送确认，挥手动画，皮肤外层和姿态元数据。实体生成等待对应地形交付完成。
- 天空光照和方块光照根据方块状态的不透明度、发光强度及面遮挡计算，支持跨区块传播、移除光源、光照更新包和 Anvil 持久化。
- 方块破坏，以及创造模式主手／副手放置；通过方块变化包广播，并直接保存到 Anvil。
- 玩家物品栏、盔甲、副手及选中的快捷栏槽位在退出和重启后保留，包括精确的网络物品组件。标准 Java Inventory NBT 可导出常见组件：名称、描述、耐久、附魔、药水、食物和嵌套容器。不支持的复杂 Java 数据导入会明确报错。玩家菜单点击由服务端按实际状态处理，支持拆分／合并、Shift 转移、数字键／副手交换和拖动分配。
- 创造模式交互距离检查、客户端预测确认和放置拒绝纠正；不能覆盖固体方块或玩家身体。原木轴向、楼梯、台阶合并、持久树叶和双格植物具有基础放置规则。移动检查使用从原版 JAR 提取的碰撞箱，覆盖半砖、台阶和潜行时的顶部空间。
- 门会放置上下两部分，可从任一部分开关；活板门、栅栏门、拉杆和按钮支持基本交互状态。墙上火把、灯笼和开关遵循附着规则，失去支撑的附着物和门会被移除，包括跨区域更新。栅栏、铁栏杆和玻璃板会更新连接状态。观察者会收到可见玩家的主手、副手和盔甲装备更新。
- 基础方块更新会移除失去支撑的草、花和双格植物的上下两部分。沙子、红沙和沙砾会排入延迟重力更新。显式执行计划更新时，支持下落实体及掉落物的创建和持久化；与默认时钟、区块票据的集成，以及掉落物后续生命周期仍未完成。
- 聊天消息转发（系统聊天），以及保活心跳和响应不匹配时的断开处理。
- Java 世界存档：方块修改、世界年龄、一天中的时间、天气、玩家位置、物品栏和创造飞行状态可跨重启保存；玩家加入时优先收到自己所在的区块。
- 可加载现有 Java 版 1.21.1（DataVersion 3955）的 `level.dat`、主世界 Anvil 区块及 `playerdata/*.dat`。修改后的区块写回 `.mca`，玩家位置、飞行和物品栏写回原版 NBT。
- 新建普通世界和不含结构的超平坦世界时，使用 Java 版 1.21.1 的 `level.dat` 和 Anvil 格式。旧版 Atlas 丘陵生成、`level.json` 和 `blocks.log` 路径已移除。
- 主世界的纯 Go 噪声、生物群系、地表和雕刻阶段已与参考 JAR 对照，包括最初的 12 个区块，以及额外的 45 个山地、高原和洞穴区块。地物的顺序、种子、定义、部分放置候选点、矿脉、森林岩石、蓝冰，以及精确的阻挡运动高度和海底高度也有原版检查。**Feature 统一译为“地物”**，相关概念见[术语表](GLOSSARY.md)。
  新建普通世界和生成缺失区块时，会执行这些阶段以及已支持的装饰生成：矿石、森林岩石、蓝冰、黏土／沙砾圆盘、全部内置主世界树木配置、草／蕨、双格植物、花、枯死的灌木、浆果丛、南瓜、仙人掌、甘蔗、睡莲和巨型蘑菇。
  生成版本 12 还加入了泉水与冻结、溶洞和繁茂洞穴地物、幽匿斑块与幽匿脉络、小型蘑菇、晶洞、熔岩湖、杜鹃树及其根部生成、海洋植被与珊瑚、冰山、竹子与灰化土、西瓜、方块堆、沙漠水井和怪物房间。
  生成的箱子、刷怪笼、可疑的沙子、蜂巢和幽匿相关 NBT 会保存并包含在区块数据包中；刷怪笼的生物更新仍不完整。单箱菜单支持由服务端控制的物品转移和持久化，村庄／前哨站战利品表支持非零的已保存战利品种子。其他容器类型和战利品表仍不完整。
  植被包含原版加权和基于噪声的提供器，已对照 4,208 组已配置／已放置地物样本。沙子／草方块圆盘包含规则提供器和后处理，已对照 96 组原版样本。全部 31 种树木配置均有官方参考数据，包括巨型树、樱花树、红树和六种树木装饰器。
  沙漠神殿、丛林神庙、沼泽小屋、雪屋、埋藏的宝藏、主世界六种废弃传送门、沉船、海底废墟、废弃矿井、古迹废墟、试炼密室、远古城市、掠夺者前哨站、全部五种村庄及要塞，均已实现结构起点、方块、方块实体、战利品种子和持久化引用。已支持的结构 NPC 和 18 种初始动物会生成，并与地形分开保存。
  海底神殿和林地府邸补齐了主世界 29 个结构定义的起点／放置覆盖。相邻区块的装饰和光照阶段顺序仍不完整。主世界 151 个顶层已放置地物方案已全部启用；这是实现覆盖率，不是与原版世界一致的百分比。完整装饰后的世界尚未与原版完全一致。
- 纯 Go 下界和末地生成覆盖生物群系、噪声、地表、下界洞穴，以及全部 37 个下界和 5 个末地地物方案。下界要塞、下界化石、下界废弃传送门和堡垒遗迹已接入实际区块／存档流程。末地城包含战利品箱、潜影贝和装有鞘翅的物品展示框。
  生成的气泡柱和跨树木的树叶距离保留延迟请求，在生成后通过显式计划更新执行。主世界所有结构类别均已启用。生成期间的流体请求在 `fluid_ticks` 中保留原始类型、优先级和顺序；更完整的方块处理器、默认时钟／区块票据集成，以及完整世界一致性仍未完成。
  玩家可以切换维度，维度、位置、物品栏和修改内容可跨退出／重启保存。生成的末地水晶和已支持的结构 NPC 保存在各维度独立的实体区域文件中，并在地形交付后发送。现有盔甲架支持装备交换、向所有观察者同步更新和 Anvil 持久化；放置、破坏、AI、物理和伤害行为仍不完整。
- 打火石和火焰弹可以激活有效的下界传送门框架。玩家接触传送门时使用原版创造模式延迟和冷却、8:1 坐标换算、现有传送门搜索、出口创建、相对位置和碰撞检查。主世界末地传送门会重建原版末地抵达平台；末地返回、折跃门移动、门框破坏清理和末影龙战斗仍不完整。
- 每秒 20 tick 的世界时钟，以及晴天、雨天、雷暴天气控制。
- 客户端命令树、聊天命令和控制台命令：`help`、`list`、`where`、`tps`、`mspt`、`status`（`sysinfo`）、`seed`、`op`、`deop`、`time`、`weather`、`tp`、`setblock`、`save`，以及 `execute in <dimension> run tp|setblock`。后者仅支持这个子集，并非完整的 `execute` 命令分派。
- 带类型的原版命令参数、服务端玩家名补全，以及已支持命令的原版命名空间别名。点击帮助条目可插入命令；消息支持命名颜色和 RGB 文字颜色。
- 使用 `server.properties` 配置地址、端口、MOTD、人数上限、在线模式、视距、向客户端声明的模拟距离、世界路径和种子；使用原版形式的 `ops.json` 持久化管理员，并校验 UUID。
- 原版风格的可读日志：`[HH:mm:ss] [Server thread/INFO]: ...`，包含启动字符画、构建时间、玩家聊天和执行的命令；提供独立调试日志和可选的数据包跟踪。

## 世界、命令与日志

Atlas 目前仅使用 Java 版 1.21.1 的 `level.dat`、Anvil 区域文件和 `playerdata`。旧版 Atlas 丘陵及其 `level.json`／`blocks.log` 格式不再加载或创建；复用旧目录前，请先备份旧 Atlas 世界。方块修改在确认前写入 Anvil。世界元数据和在线玩家每 30 秒及正常关闭时保存，玩家断开连接时也会保存。

服务器目录下缺少 `server.properties` 或 `ops.json` 时，Atlas 会创建它们。支持的配置项包括 `server-ip`、`server-port`、`motd`、`max-players`、`online-mode`、`view-distance`、`simulation-distance`、`level-name`、`level-seed` 和 `level-type`，以及 Atlas 扩展项 `spawn-preload-radius` 和 `chunk-generation-workers`。其他配置项会在启动时报告为已忽略。显式命令行参数优先于这些配置。

视距和模拟距离目前都支持 2～16 个区块。区块传输和玩家可见范围取服务端与客户端视距设置中较小的值。模拟距离会写入加入世界的数据包，但 Atlas 尚未实现该半径内完整的原版实体和方块更新。

新建普通或超平坦世界时，留空 `level-seed` 会随机选择种子；支持数字和文本种子，文本使用 Java 字符串哈希。种子保存在 `level.dat` 中。新的超平坦预设使用原版四层地形、平原生物群系，并禁用结构和地物。现有 Java 世界保留原有种子。

默认的 `minecraft:normal` 会创建包含生物群系、地表、洞穴、矿石和已支持装饰的噪声世界。新普通存档启用已支持的结构（`generate_features=true`）；现有存档保留自己的开关和完整区块。`AtlasWorldgen` 元数据记录实现尚不完整，生成的区块会列出跳过的阶段。

新普通世界使用原版初始出生点搜索：创建存档时执行基于气候的搜索（`Climate$SpawnFinder`，已有 JAR 对照），确定出生区块；首次启动时，再按原版 11×11 区块螺旋顺序按需加载，找到安全位置后才允许玩家加入。Atlas 还会检查站立空间、建造高度上限、流体和伤害方块。空种子会让新世界各不相同，固定种子可复现相同初始出生点。结果保存到 `level.dat` 并跨重启保留。运行时可用 `/setworldspawn` 移动出生点，新玩家准确出现在保存的出生点；已有位置记录的玩家使用自己的位置。

全部 31 种内置树木配置及其树苗判定条件已有原版检查。蜂巢候选位置的打乱使用保存在 `level.dat` 中的独立随机盐，再为每次树木生成调用派生稳定的键，以保持相邻区块重放和重启的一致性。这个随机源与原版的进程全局打乱不同。生成版本 12 已在新区块中接入装饰与已支持结构；现有完整区块保留已保存的方块。

在打开监听端口前，Atlas 会按由近到远的顺序加载并保存出生点周围的方形区块区域。`spawn-preload-radius=3` 会准备 49 个区块；支持的半径为 0～16，设为 0 时仍预加载最终出生点所在的区块。

新普通存档的安全搜索独立于此半径。它使用方块列扫描、阻挡运动／世界表面／海底分类、逐状态碰撞和流体参考数据，以及额外的空间和危险检查，保存首个安全位置。找不到安全位置时，启动会失败，并保留“初始出生点尚未完成”的标记，不会接受未经检查的高度。配置的预加载区域以最终出生点为中心。现有存档启动时也会执行预加载，但不会重新生成已有区块。预加载半径独立于视距和模拟距离，不会启用出生区块票据或实体更新。启动日志会显示进度和耗时。

`chunk-generation-workers=0` 时，自动使用可用 Go CPU 线程数的一半，最少 1 个、最多 8 个。可显式设置正数，最大 256。`-gen 4 -spawn-radius 5` 会覆盖配置，使用 4 个生成工作线程并准备 121 个区块。探索世界时请求的区块也由同一个工作池生成。

生成使用不可变的共享地形、私有装饰覆盖层和区域 actor 层的重复请求合并；关闭时会等待正在运行的生成任务结束。启动过程中中断会取消准备工作，已经生成的区块仍可在下次启动使用。

每次 30 秒自动保存后，位于玩家视图及其一圈区块边界之外、且一分钟未使用的区块会被保存并卸载，释放其光照和数据包缓存。待处理请求和最近的直接访问会保留区块；保存失败也会保留区块。区域 actor 和有容量上限的基础地形缓存仍会保留，Go／Windows 内存计数下降可能晚于缓存数量下降。

读取区块时只读取目标 Anvil 记录。替换区域文件时，通过固定大小的缓冲区流式复制未修改记录，而不是复制整个文件。区域读取和替换使用按区域管理、数量受限的锁；解压、NBT 解析和压缩在锁外进行。压缩写入器和光照工作数组会复用。每个区域 actor 最多缓存 64 个已编码区块包，总容量最多 2 MiB，方块或光照变化时会刷新。

生成会预编译密度运算和地物放置方案，使用紧凑含水层网格及稀疏装饰覆盖层，只构造最终请求的区块。版本 10 的输出哈希包含生成的方块实体，并接受顺序和并行检查。早期性能测量见[区块加载与生成性能](artifacts/chunk-performance-v2/validation.md)。英文版还引用了以下本地历史报告，当前工作区未包含这些文件，因此此处保留路径供查找：

- 世界生成版本 12 的新增内容、覆盖范围和验证：`artifacts/worldgen-v12-validation.md`。
- 世界生成版本 5 的内存重放、互操作和二进制验证：`artifacts/worldgen-v5-validation.md`。
- 世界生成优化与冷启动验证：`artifacts/worldgen-probes/performance-v8.md`。

游戏玩法目前仍以创造模式为主。玩家垂直运动仍由原版客户端驱动，服务端移动验证检查方块碰撞。碰撞表是在原点、空碰撞上下文中提取的；依赖位置或实体的形状，例如竹子偏移、细雪和脚手架，仍需要专门规则。床、其他方块交互、流体完整行为、红石／活塞运动、随机刻、生物、掉落物、其余容器菜单、合成和生存机制仍不完整。相关历史验证为上文的版本 12 报告，最新生成状态见[世界生成概览](docs/worldgen/README.md)。

对于现有 Java 版 1.21.1 存档，请将存档目录的**副本**传给 `-world`。Atlas 读取 `level.dat`、现有主世界 `region/*.mca` 区块和 `playerdata/*.dat`，并将修改后的区块 NBT、时间／天气、世界出生点，以及玩家位置、旋转、飞行、物品栏和出生点写回这些原版文件。未修改的 NBT 标签会保留；替换 `level.dat` 或玩家数据前，会保存 `.dat_old` 副本。

支持原版下界／末地目录及独立实体区域文件；实体行为、其余物品栏行为和世界机制仍不完整。使用内置主世界／下界／末地噪声与生物群系预设的缺失区块会在 Go 中生成。不生成其他噪声预设、启用了自定义数据包的世界、现有但尚未完成生成的区块，以及启用了结构／地物的超平坦世界。

已有完整区块会被保留。装饰生成使用私有的相邻地形数据，因此新区块不会覆盖玩家已经保存的修改。仓库中的 `jar/server.jar` 只用于参考，Atlas 运行时不会调用它。不要让 Atlas 直接使用原始的 `vanilla/world` 样本，也不要让两个 Atlas 进程同时使用同一个存档目录。

公开的游戏内命令为 `/help`、`/list` 和 `/where`。传给 `-ops Alice,Bob` 的玩家名可以使用世界命令，控制台始终可以使用这些命令：

```text
/tps
/mspt
/status   (alias: /sysinfo)
/time query [daytime|gametime|day]
/seed
/op <player>
/deop <player>
/time set day|noon|night|midnight|<time>
/time add <time>
/weather clear|rain|thunder
/tp <destination player>
/tp <player> <destination player>
/tp [player] <x> <y> <z>
/setworldspawn [x y z [angle]]
/spawnpoint [player] [x y z [angle]]
/setblock <x> <y> <z> <block[state=value]|1.21.1_state_id> [replace|keep]
/save
/save-all [flush]
```

命令树使用原版的位置、玩家、方块状态和时间参数类型，玩家名 Tab 补全由服务端提供。`/help [command]` 会显示当前允许使用的命令，条目可点击。原版别名包括 `/teleport`、`/save-all [flush]`，以及已支持原版命令的 `minecraft:` 前缀。`save`／`save-all` 会先保存在线玩家，再保存世界元数据。必填参数未填完时不会提前标记为可执行；多余参数会返回用法错误。

`/tp <player>` 将发送者传送到另一位在线玩家；`/tp <player> <destination>` 也可在控制台使用。位置参数支持绝对坐标、`~` 相对坐标和 `^` 局部坐标。相对坐标以命令发送者位置为基准，控制台以原点为基准；`@s`／`@p` 分别选择发送者／最近的在线玩家。

与原版一致，传送命令中的整数绝对 X/Z 坐标会居中到方块，例如 `34 85 -17` 变为 `34.5 85 -16.5`。需要精确边缘坐标时应使用小数。传送目标遵循原版可生成范围：X/Z 必须 `>= -30000000` 且 `< 30000000`，Y 必须 `>= -20000000` 且 `< 20000000`。传送 Y 不受方块建造高度限制。命令被拒绝时会说明范围，并保留玩家位置和待处理地形请求；例如 `/tp 1000000000 ~ 1000000000` 超出原版 X/Z 范围。

`/setblock` 接受全部已知的 1.21.1 方块名和属性，例如 `minecraft:oak_log[axis=x]`，也接受数字状态 ID。`keep` 只替换空气，默认模式是 `replace`。`/time query` 接受 `daytime`、`gametime` 和 `day`；数字形式的时间设置／增加支持 `t`、`s` 和 `d` 单位。

`/setworldspawn` 和 `/spawnpoint` 遵循原版 1.21.1 默认值：省略位置时使用发送者的方块位置，控制台使用原点；`/spawnpoint` 的默认位置来自发送者，而非目标玩家。省略角度时为 0。角度接受普通度数或相对发送者朝向的 `~`／`~-5`，并归一到 [-180, 180)。

`/setworldspawn` 将 `SpawnX/SpawnY/SpawnZ/SpawnAngle` 保存到 `level.dat`，向所有已进入游玩阶段的玩家广播新出生点，并准备周围区块，作用类似原版出生区块票据的准备过程。新玩家准确出现在保存的位置。`/spawnpoint` 将原版 `SpawnX/SpawnY/SpawnZ/SpawnAngle/SpawnForced/SpawnDimension` 标签写入玩家数据，供后续重生处理使用。

命令和选择器语法目前仅覆盖原版子集；完整选择器过滤、多目标传送、传送朝向参数、天气持续时间，以及 `setblock destroy` 尚未实现。

游戏文字使用结构化的匿名 NBT 文本组件，不依赖字面上的分节符颜色代码。成功／错误使用绿色／红色，标签使用青色／灰色，TPS 使用绿色（18 及以上）、黄色（15～18）或红色（低于 15）。欢迎消息、聊天名字和服务器列表 MOTD 支持样式文字。旧式 `§0..§f`、格式／重置代码、`§#RRGGBB` 和 `§x§R§R§G§G§B§B` 会转换为组件样式，控制台和文件日志保持纯文本。NBT 文字使用 Java modified UTF-8，支持 NUL 和 emoji 等补充平面 Unicode 字符。

Java 版 1.21.1 的玩家实体使用运行时注册表 ID **128**。按字母排序的实体名称索引 82 在运行时注册表中对应药水，不能作为玩家 ID。玩家档案先于实体生成发送，随后发送皮肤／姿态元数据和装备。实体跟踪等待观察者的地形交付，并处理离开、重连和重新进入视野。

成功加入和后续离开会向所有已进入游玩阶段的玩家广播黄色的原版翻译组件，包括加入者本人以及实体可见范围外的观察者。加入失败不会产生离开公告，加入／离开文字由客户端语言决定。

独立开发检查可通过 `ATLAS_COMPAT_FIXTURES` 导出协议参考文件，再使用参考 JAR 和 `python tools/protocol/verify_player_entity.py <fixtures-directory>` 解码。服务端运行时不需要参考 JAR。

性能命令需要管理员等级 2 或控制台权限。`/tps` 显示最近 1、5、15 分钟内，每秒实际完成的世界时钟循环数，上限为目标值 20。窗口尚未填满时只使用已观察到的运行时间；首个 tick 之前会提示正在收集样本。世界时间追赶时，错过的循环不会被算作已完成 tick；即使卡顿，也会把距上次 tick 的时间计入。

`/mspt` 显示最近一分钟时钟工作的平均值、P95、最大值、超过 50ms 的工作次数、已完成循环之间的最大间隔、距上次 tick 的时间，以及周期自动保存的最近／最大耗时。工作耗时不包含定时器等待和保存，但保存仍会影响循环间隔和 TPS。

`/status` 还显示运行时长、在线人数、goroutine 数、Go 版本／平台、CPU 数量／并行度、已分配堆内存和 Go 管理的内存、GC 暂停、上次回收时的存活堆大小和下次 GC 目标，以及缓存区块／光照列、区域 actor、活跃生成工作线程、区块任务队列和 actor 邮箱深度。

Windows 下还会读取原生进程 CPU 使用率和驻留工作集，其他平台目前将这两个字段报告为不可用。CPU 使用率取自上次状态查询以来的平均值，首个样本从服务器创建时开始计算；250ms 内的重复查询会复用前一个平均值。100% 表示占满一个 CPU 核，因此多核生成时可超过 100%。Go 内存和驻留工作集是不同指标。

世界计数器提供尽力而为的快照，不会等待 actor 或生成任务。时钟 TPS/MSPT 不衡量并行区块生成和玩家处理工作，应结合 CPU、内存和队列一起查看。固定容量历史最多保留 15 分钟的 tick，仅在查询时对延迟样本排序。

服务端程序的默认值为 `online-mode=false`。设置 `online-mode=true` 后，Atlas 会在登录前向 Mojang 验证客户端会话，并使用官方 UUID 保存玩家。已有离线模式玩家数据和 OP 条目使用不同 UUID，不会自动迁移。在线模式下，应在玩家加入后通过控制台 `/op <player>` 授权；`-ops` 只知道离线 UUID，因此在线模式会拒绝该参数。在线模式中，尚未连接的玩家不能预先授予 OP。

控制台命令可以省略开头的斜杠。控制台输入 `stop` 会保存并关闭服务端。使用 `-log-file` 和 `-debug-log-file` 修改日志路径；`-debug` 将详细事件写入 `logs/debug.log`，`-trace-packets` 还会向该文件写入移动等高频数据包日志。每次运行都会创建新的活动日志，达到 10 MiB 时轮转，并保留三份备份。

## 架构

模块职责、数据归属，以及登录／方块修改／区块请求流程，见[架构指南](docs/architecture.md)。领域用语见[术语表](GLOSSARY.md)。

```text
TCP :25565
  │ net.Listener：接受连接
  ▼
每条连接的一对 goroutine
  ├─ 读取循环
  └─ 写入循环：消费有界 p.Out；客户端过慢时断开，不阻塞区域
  │
  ▼
Hub：玩家注册表；通过 ViewersOf(x,z) 查询观察者
  │ 邮箱消息（channel）
  ▼
Region actor：每个 32×32 区块区域由一个 goroutine 管理
  │ 区块状态只由所属 actor 修改；共享世界管理器负责同步
  │ genJob（channel）
  ▼
区块生成工作池：纯函数，相同输入得到相同区块
```

- **区域 actor**：方块修改和区块请求均通过消息传递，由所属区域的 goroutine 应用，再通过 `Hub.ViewersOf` 分发方块变化包。跨区域修改由世界层协调，并通过区域消息执行。
- **背压**：所有发送队列都有容量上限。客户端落后时会被断开，不会拖住区域 actor。
- **生成边界**：普通区块执行已验证的地形阶段和已支持地物；完整装饰和结构行为仍不完整。跨区块装饰按固定顺序重放相邻来源，使用不可变、有容量上限的地形缓存，只写入请求的目标区块。
